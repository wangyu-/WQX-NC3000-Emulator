# NC3000 模拟器 ROM 装法（已实测确认，2026-09-26）

## 1. 结论

```
<rom>.nor    1 MB，32 个 bank（32KB/ bank）
<rom>.nand0  设备 NAND 的**第 0~63 页**（64 × 528 = 33,792 字节）
<rom>.nand   设备 NAND 的**第 64 页到最后一页**（131,008 页 × 528 = 69,172,224 字节）
```

**`.nand` 不是"整个 NAND"，而是从第 64 页开始的剩余部分**——这一点很容易搞错，
而且装错会**整体偏移 64 页**，固件直接跑飞（画面变成细密网纹乱码）。

## 2. 怎么确认的

1. 加 `--dump-nand-page`，把模拟器**实际看到的设备页**打出来：

```
page 0  : 01 00 BA 80 C0 7A ...   ← 来自 <rom>.nand0
page 64 : 4A 55 3F 96 C3 57 ...   ← 来自 <rom>.nand 的第 0 字节
```

   即 `.nand0` 落在设备页 0~63，`.nand` 落在设备页 64 起 ✓

2. 逐字节比对：`info/NC3KSYSNAND.nand`（我们的 dump）与 Lee 版
   `data/nc3000.nand` **在共同长度 53,779,970 字节上差异为 0**；
   Lee 的文件只是更长，总长 69,172,224 = **131,008 页 = 131,072 − 64**。
   → **两边是同一份镜像，都是"设备第 64 页起"**。

## 3. 三种装法的实测对照

| 装法 | `.nand0` | `.nand` | 结果 |
|---|---|---|---|
| **A（错）** | Lee 文件前 64 页 | Lee 文件从第 64 页起 | **乱码**（整体再偏 64 页） |
| **B（对）** | 我们 dump 前 64 页 | Lee 文件**原样** | 能进系统：统计中… → 网络菜单 |
| **C（对，推荐）** | 0xFF（我们没有真数据） | Lee 文件**原样** | 同 B（说明这 64 页不影响启动） |

> 教训：`--dump-nand-page` 这种"直接问模拟器你看到了什么"的调试开关，
> 比任何推理都快——这个坑已经绕了三轮。

## 4. 当前推荐的 ROM 目录

```
roms/lee2/
  nc3000.nor     1,048,576 B      （Lee 版发行包里的完整 1MB NOR）
  nc3000.nand0      33,792 B      （0xFF；设备前 64 页，暂无真数据）
  nc3000.nand   69,172,224 B      （Lee 发行包里的 nc3000.nand，原样使用）
```

# 6. ★ 2026-09-26 晚：上面那条"少了 LOGO"的根因找到了（已修）

## 6.1 根因：NAND 里缺 `"ggv nc3000"` 签名

NC3000 的 BIOS 在启动早期会去**闪现里找自己的签名串**（NOR 里 bank 0
`$BAC8` 处就写着这个常量 `"ggv nc3000"`，旁边的代码是 NGFFS 的坏块标记
例程）。找不到签名，固件就**不认为这是"有数据的系统盘"**，于是不进
开机动画，而是走 **"系统升级"模块**：先做一次系统空间整理/CRC，再等
PC 端通讯，超时后**直接关机（clk off）**。

Lee 的模拟器没有 `.nand0` 文件——它是**自己合成这 64 页**的（用户原话：
"`.nand0` 是模拟器自动生成的"）。而本仓库的移植版把 NC2000 那段
"写入签名"的代码用 `#if 0` 关掉了（`nand.cpp` 里 `nc3000mode` 分支），
于是 64 页全是 `0xFF`，签名读出来是乱的（启动日志里那句
`nand magic: ??????????` 就是它在报警）。

### 修法（`src_nc3000/nand.cpp`，`read_nand_file()` 末尾）

```c
if(nc3000mode){
    memcpy(&nand[0][0]+0x200+0x10 /* 页 1 + 0x10 */, "ggv nc3000", 10);
}
```

（NC2000 是 `"ggv nc2000"`、NC2600 是 `"ggv nc2010"`，位置相同。）

顺带补了一处：`nc2000.cpp` 里 `sync_time_*()` 原来只对 nc2000/nc1020 调用，
NC3000 一上电 RTC/日期寄存器是全 0，现在开机也同步一次主机时间。

## 6.2 修好之后的启动时序（与真机/Lee 版一致）

证据图：`out/nc3000/启动时序_全新.png`（每 500 ms 一帧，14 秒）

| 时间 | 画面 |
|---|---|
| 0–3.0 s | 「系统空间整理中 请稍候...」 |
| 3.5–4.2 s | 「闪存中有数据 清除吗？ Y清除，N保留」 ← 按 **N**（保留） |
| 4.5–5.0 s | 「名片数据正在整理中 请稍候」+ 进度条 100% |
| 5.5 s 起 | **授权画面**（剑桥/AHD 两面国旗/"英美权威双授权"）⇄ **文曲星 NC3000 LOGO**（AHD 词典书 + 文曲星 + NC3000）**反复切换** |

> 注意：这条冷启动路径**必须回答"闪存中有数据，清除吗"**（按 N）。
> 之前"唤醒 → 统计中 → 网络菜单"其实是被签名缺失带进了升级模块。

## 6.3 反复切换画面上的按键实测（与用户描述逐条吻合）

在切换画面上按**顶部 8 个按键**（矩阵列 0，行 0~7），固件把
`$03E3 (Curr_Function)` 写成：

| 矩阵位置 | $03E3 | 用户给的标签 | 实测画面 |
|---|---|---|---|
| (0,0) | 0C | 开/关 | 关机（黑屏） |
| (1,0) | 04 | PDA/游戏 | 名片/记事/行程 图标菜单 |
| (2,0) | 02 | 计算/换算 | 计算器（Memory 0.） |
| (3,0) | 00 | 时间/系统 | 时钟/日历 + 开机题词 |
| (4,0) | 01 | **网络** | ⚠️ 见 §6.4，模拟器里变成关机 |
| (5,0) | 06 | 英汉/汉英 | 英汉辞典（请输入英文） |
| (6,0) | 08 | AHD/词库 | 经典美语大辞典 |
| (7,0) | 0A | 剑桥/学习 | 剑桥双解大辞典 |

证据图：`out/nc3000/功能键实测.png`。

另外：在切换画面上按**任意字母键**（矩阵列 4~7 的 32 个位置都会命中），
画面会停在**静止的 NC3000 LOGO** 上——这就是真机那句
"出现 LOGO 那个反复切换的画面后，得按确认键它才会进主菜单"里
"按过键之后"的状态。

## 6.4 仍未解决（下一步）

1. **(4,0) 网络键 → 模拟器黑屏/关机**：实测按下去以后 PC 会跑到
   `$E36D`（`LDA #$FF / STA $05 / JMP` 的 clk off 死循环）。
   真机这里应该出「应用程序/文书浏览/有声学习/和弦音乐/歌曲音乐」列表。
2. **静止 LOGO 之后进不到 2×6 主菜单**：那一步固件在 RAM `$05E7` 的循环里等
   `$0408` 的 bit7（UART/061 事件），我们的 061 桥接没有把事件递上去
   （`[061] sent=0 recvd=0`）。要查 `iv_uart.cpp` 的 `write_3a/read_3a`
   是否被 `TMR&0x20` 挡掉，以及 `$FCF3` 那段 `0xAA` 握手。

### 6.4.1 2026-09-27 追加：这两条的成因已经查清（还没修）

* 冷启动走完动画那一段，固件自己把 `$03E3 = 1（网络）`、`$03E4/5 = A5 5A`
  写好了（RAM `$414x` 那段，见 `$414B`–`$416E`），也就是说
  **机器其实是"进到网络功能里"在放开机动画**——这就是为什么之前
  动画之后会冒出来"应用程序/文书浏览/…"那个列表。
* **静止 LOGO 卡住的机制**：固件在 bank 3 `$B97F`（RAM `$797F`）循环
  「等键 → `INT $C006`(repeat_key) → 和 `#$0D`（输入）比较 → 相等就
  `$CE = $FF`」。它要求 `$C7` 的 **bit7 = 1（有新键）**；
  实测我们按 (5,3) 之后 `$C7` 是 `0x79`（bit7=0，"键按着"），
  所以 `$CE` 永远是 00，循环退不出来。
  → **根因是"新键边沿"没被固件认到**，要查扫描收尾那段
  （bank 0 `$EF09`–`$EF31`，配合 `$03ED` 的 bit7）。
  更正后的 `$C7` 语义见 `docs/NC3000_按键矩阵实测.md` 第 8 节。
* 顺带：动画的"反复切换"是**每秒一次的超时轮询**（动画例程 bank 3 `$8C0E`
  里用 `$03FE`(RTC 秒) 做超时），不是等按键才翻页。
