# SPCE061A 模拟器 + A1600/MS01 播放器：可行性结论与实施计划

## 0. 先说结论（基于实测，不是估算）

| 需求 | 可行性 | 关键依据 |
|---|---|---|
| C 语言 SPCE061A 模拟器跑 061.dat | **可行** | 已用自研解释器实测：忽略 0x8000-0x81FF、从 0xCB9F 复位入口启动，配合外设桩后 **72310 条指令即进入主循环 0x8232** |
| 在 STM32F411 上实时出声 | **可行但需优化** | 实测 A1600 解码 = **17161 条 µ'nSP 指令/帧**（128 样本 = 16ms）→ 约 1.07M 指令/秒；音频 FIQ 中断体仅 11~15 条 → 8kHz 下再加 0.1~0.2M/秒。合计 **约 1.3M 模拟指令/秒**，STM32F411（100MHz M4）用 switch 解释器（-O2）通常能到 3~8M/秒 |
| Linux 命令行 A1600 播放器 | **可行，且已验证** | 见 `a1600_decode.py`（Python 版已解出正确音频）；C 版只是把解释器换语言 |
| Linux 命令行 MS01 播放器 | **可行，但需要多一步逆向** | MS01 引擎不在固件里（不是 SDK 版本），需从 `SACM_MS01_V4.1.3.lib` 提取：**kernel CODE=1688 字 + TEXT(表)=1092 字**，规模很小 |

## 1. 模拟器（C / STM32F411）

### 1.1 已经打通的部分

- **µ'nSP 指令语义**：已按 MAME unsp 核实现（ALU/标志位/移位 SB/间接寻址 DS/条件跳转/`call`+`retf` 栈约定），MAME 未实现的 `MULS` 按手册 3.3.6 实现并在真实音频上验证通过 ✅
- **启动路径**：0x8000-0x81FF 缺失可以忽略——真正的复位入口是 **0xCB9F**（设栈→按 0x824B 拷贝表搬运→`call 0x8205`），而 CPU 向量区 0xFFF5-0xFFFF 的内容可以从映像里的 **0xFC00 向量表**（C889/C742/CB9F/C895×7/C889）合成 ✅
- **握手**：固件上电后要等两个"外部就绪"字节（约 0x0ABB 与一个非零命令），喂进去就进主循环 ✅

### 1.2 需要新写的外设（按固件实际访问过的端口，共 22 个）

| 模块 | 端口 | 说明 |
|---|---|---|
| I/O 口 A/B | 0x7000-0x7008 | A 口只初始化；**B 口有周期读写**（`0xCBC4` 轮询 IOB bit2），按键/外设状态需要建模 |
| 定时器 A/B | 0x700A-0x700D | 音频时基，必须准（TimerA 触发 FIQ） |
| 中断控制 | 0x7010/0x7011/0x702D | FIQ/IRQ 使能、清标志、屏蔽 |
| 看门狗 | 0x7012 | 固件在长循环里持续喂狗，模型可只记录 |
| 系统时钟 | 0x7013 | 仅记录（模拟器不需要真时钟） |
| ADC/DAC | 0x7014-0x7017、0x702A/0x702B | DAC1/DAC2 输出 = 播放采样点；ADC 是录音/麦克风通路 |
| UART | 0x7021-0x7025 | **同时是调试口和固件协议口**，建议直接桥接到宿主串口 |
| 系统保留 | 0x7555 | flash 控制器，固件未使用 |

另外要**实现 FIQ/IRQ 真正的中断处理**（我的 Python 版目前只跑主流程）：触发时压 PC/SR、跳到合成出来的向量地址。这是 C 版相对 Python 版必须补的部分。

### 1.3 STM32F411 资源与实时性

- **Flash**：061.dat 64KB + 解释器/外设约 20-40KB，512KB 够用（映像可放 flash 直接当 ROM 读）✅
- **RAM**：模拟 RAM 2K 字（4KB）+ 音频双缓冲（8kHz×2 通道×32ms ≈ 1KB）+ 解释器状态，远小于 128KB ✅
- **CPU**：如上，实时解码约需 1.3M 模拟指令/秒；建议
  1. 用 `switch` 派发 + 把 `read/write` 做内联（RAM 区直接数组访问，ROM 区直接指针）；
  2. 音频路径用 DMA + 半满中断，UART 调试信息**限制长度/可编译关闭**（否则阻塞会破坏实时性）；
  3. 必要时 F411 超频到 120-128MHz（常见做法）。
- 若实时性仍紧，可退一档：只把**解码器**跑在模拟器里、音频输出用原生 ISR（不模拟 TimerA），这是"半模拟"模式，开销减半。

### 1.4 已知风险

1. **固件是产品固件**：它按 UART 协议接收命令、按按键触发动作。模拟器"能跑"不等于"能触发所有功能"——需要在 UART 侧把协议命令发进去（或做"外设桩"模式）。
2. **0x8000-0x81FF**：固件运行路径没有读它（已实测），但**中断向量必须补**（用 0xFC00 的表生成 0xFFF5-0xFFFF），否则 FIQ/IRQ 会跳飞。
3. 若产品固件依赖 IOB 上的外部芯片（如按键矩阵/传感器），需要按现象逐步补模型。

## 2. Linux 命令行播放器

### 2.1 A1600（最简单，已经跑通）

架构：**C 解释器 + 内嵌映像**。两条实现路线：

| 路线 | 做法 | 优点 | 代价 |
|---|---|---|---|
| A. 复用固件解码器 | 把 061.dat（或只抽 A1600 内核 0xB5CB-0xC0C3 + fft64 0xCFE8-0xD1E0 + 相关表）内嵌，用同一套 C 解释器跑 | 与实机位级一致，已验证 | 要内嵌映像（整片 64KB 或抽取后约 6KB） |
| B. 原生 C 重写解码器 | 按反汇编实现解包+逆 FFT+两级内积 | 快、干净 | 工作量大、需再验证 |

建议先 A（能立刻出声），后续再考虑 B。

命令行形态：

```
a1600play /abs/path/sound.a16            # 直接播放
a1600play -o out.wav /abs/path/sound.a16 # 转 WAV，便于核对
```

出声方式：ALSA（`libasound`，最通用）或最简方案写 `/dev/dsp`；转 WAV 则纯文件 IO，零依赖。

### 2.2 MS01（需要补一步逆向）

MS01 播放 = **乐谱解释 + 波形/包络合成 + 鼓点 ADPCM**。需要三样东西：

1. **乐谱格式**：`.POP` 是**文本谱**（Midi2Pop 说明书里有完整示例：`|5 6 5 - 6 - ...|`，每行一个通道，`-` 表示 16 分音符延续，行首有 `*04/04`、速度字节等）→ **可以直接解析文本**，无需逆向 .BIN。
2. **合成引擎**：`.lib` 里 `MS01_kernel` 的 **CODE=1688 字 + TEXT=1092 字（波形/包络表）**，规模很小。两种用法：
   - 用 C 解释器直接跑（需要解决模块重定位：库里的跨段地址是"段内偏移"，链接时要加基址）；
   - 或者把这些表提取出来 + 按 kernel 逻辑用 C 重写（工作量大些，但产物干净）。
   
   好消息：**A1600 内核我已经同时拥有"库版"和"已链接版"（固件）**，可以拿它当标尺，把"库里哪些字需要重定位"的规则验证出来，再套到 MS01 上。
3. **鼓点 ADPCM**：固件里 19 个 `.ADP` 鼓点已定位（0xD33D 起，含指针表 0xCA97），`Drum.asm` 模块里有解码逻辑，需要写成 C 函数（格式类似 4bit 差分 + 步长表）。

命令行形态：

```
ms01play /abs/path/song.POP          # 文本谱直接播放
ms01play -o out.wav /abs/path/song.POP
```

### 2.3 两种播放器的共同点

两者都可以共用**同一套 C µ'nSP 解释器 + 外设桩**，只是：
- A1600 → 用固件里的解码器；
- MS01 → 用 SDK 库里的 MS01 内核（需要重定位处理）或原生实现。

## 3. 建议的推进顺序（每步都能单独验收）

| 步骤 | 产出 | 验收方式 |
|---|---|---|
| 1 | C 版 µ'nSP 解释器 + 单元测试（我把 Python 版语义直接移植） | 与 Python 版对同一段固件（0x8205→主循环 72310 条）执行轨迹一致 |
| 2 | Linux A1600 播放器（内嵌映像 + ALSA） | 播放/导出 WAV，与你确认过的 `pcm/t09_a.wav` 一致 |
| 3 | 外设模型（TimerA FIQ + INT + UART 桥 + I/O + DAC/ADC） | 模拟器跑到主循环并能从 UART 收命令；DAC 写值能出声 |
| 4 | STM32F411 移植（UART 调试 + DMA 音频） | 板子上能听到固件播放的声音，UART 打印跟踪 |
| 5 | 库重定位规则（用 A1600 标定）→ MS01 内核可运行 | MS01 内核在模拟器里跑通 demo 曲 |
| 6 | 鼓点 ADPCM 解码 + MS01 播放器 | 播放 `MS01/DRUM/*.ADP` 与 `.POP` 谱 |

## 4. 需要你确认的两件事（会影响实现方式）

1. **STM32 上音频是否必须实时？** 若"能跑 + 串口输出"即可（比如先调试固件逻辑），第 3、4 步可以简化；若要实时出声，我会按上面 1.3 的优化方案做。
2. **MS01 播放器接受哪种输入？** 我建议**直接吃 `.POP` 文本谱**（现在就能解析，不需要 Pop2Bin 的二进制格式；那个 PDF 是扫描件，信息不全）。如果你手上有 `.BIN` 二进制谱或 `SCMPL2C` 的格式说明，也可以支持。

另外，若你能提供**产品固件对应的资源文件或 UART 协议说明**，模拟器就能从"能跑"升级到"能完整复现功能"。
