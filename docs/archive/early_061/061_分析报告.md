## 1. 结论速览

- `061.dat` 是 SPCE061A 的 **16 位字、小端** 固件映像，共 32768 字（64KB），**程序区基址 0x8200**（与你的判断一致，见第 2 节实验证据）。
- 映像中 **真正的复位入口是 `0xCB9F`**，不是文件第一个字：它先设栈、按拷贝表搬运初始化数据，再 `call 0x8205` 进入常规启动代码 0x8205（清 RAM → 延时 → 喂狗 → 外设初始化 → 主循环）。
- 反汇编出 **8207 条指令、165 个子程序**，代码占 11480 字（35.6%），其余为数据/表/未编程区。
- 固件功能画像：**音频/语音处理 + UART 通信 + I/O 状态机**。音频链路由 FIQ 中断驱动（ADC 采样 → 32 点环形缓冲 → 查系数表 `MULS` 相乘 → 送 DAC2），UART IRQ 负责收发，主循环跑命令分派与状态机。
- **中断向量表位于 `0xFC00`**（11 项：`C889 / C742 / CB9F / C895×7 / C889`），对应手册中 11 个向量（`_BREAK / _FIQ / _RESET / _IRQ0…_IRQ7`）。手册注明 CPU 的向量区在 `0xFFF5~0xFFFF`、且 `0xFC00~0xFFFF` 为**系统保留区**——本映像中该保留区除这张表外全部为擦除态（`0xFFFF`），这一点见第 9 节遗留问题。

## 2. 映像格式与地址映射：怎么定下来的

### 2.1 字宽与字节序

文件 65536 字节 = 32768 字，正好等于 SPCE061A 的 32K 字 flash。字节序用**数据表自证**：

```
文件偏移 0x8200 起： 00 80 20 7C 80 78 00 75 C0 71 C0 6E C0 6B 00 69 ...
按小端读字：0x8000 0x7C20 0x7880 0x7500 0x71C0 0x6EC0 0x6BC0 0x6900 ...   ← 严格单调递减（音量/包络曲线）
按大端读字：0x0080 0x207C 0x8078 0x0075 0xC071 ...                        ← 无意义
```

小端成立。

### 2.2 基址判定（关键实验）

指令里含大量绝对地址（`call imm16`、`goto imm16`、`pc = imm16`）。**函数入口的典型特征是前一条指令是 `retf`/`reti`/无条件跳转或填充**。于是把"映像基址"当作待定参数扫描：对每个候选基址统计"396 个 `call` 的目标是否落在函数入口"。

| 候选基址 | 命中率 |
|---|---|
| **0x8200** | **348 / 396 = 87.9%** |
| 0x81FF | 328 / 396 = 82.8% |
| 0x81E7 | 155 / 396 = 39.1% |
| 0x8000 | 57 / 396 = 14.4% |
| 其它候选 | ≤ 32% |

结论：**映像基址 = 0x8200**，即文件第 0 个字是 ROM 地址 0x8200。这也解释了文件开头的 5 个字并不是代码（见 2.3）。

### 2.3 0x8200-0x8204：一条被程序自己读取的 ID 记录

```
8200: 10F7 303B 10F7 303B 283D
```

`0xCF63`（命令分派表的一个分支）会把这段数据读出来校验并上报：

```
CF63: r1 = 0xFCBB
CF65: r2 = [0x8200]        ; 与 [0x8202] 比较
CF67: cmp r2, [0x8202]
CF69: jne 0xCF71
CF6A: r2 = [0x8201]        ; 与 [0x8203] 比较
CF6C: cmp r2, [0x8203]
CF6E: jne 0xCF71
CF6F: r1 = 0xFBBB          ; 两段 32 位值一致 → 换成"有效"应答码
CF71: call 0xCFC8          ; 把结果经 UART 送出
CF73: r1 = [0x8200]        ; 再把这 5 个字逐个上报
...
CF7D: r1 = [0x8204]
```

即 `0x8200-0x8204` 是**两份相同的 32 位标识 + 1 个附加字**，代码用"两份是否一致"判断记录有效性——典型的版本号/序列号/校验记录。

## 3. 指令编码从哪来（重要说明）

你给的两份 PDF 与 ZIP 内 17 份文档，包含寄存器映射、寻址方式、指令语法/周期/标志位、伪指令集、库函数说明，但**都不含 µ'nSP 指令的二进制编码（opcode 位域）**：第 3 章里那些位图是移位器 SB 寄存器的示意，不是指令编码；把全部 PDF 转文字并检查图片型页面后确认没有编码表。

因此编码取自**公开的 MAME unSP 反汇编器源码**（`src/devices/cpu/unsp/unspdasm*.cpp`，Segher Boessenkool / David Haywood，GPL-2.0+）。其中基类 `unsp_disassembler`（ISA 1.0）正对应 SPCE061A 这一代 µ'nSP 内核（不含 SPG 系列的扩展寄存器/位操作指令）。

反汇编前又用固件自身做了三重校验：启动序列语义正确、`retf/reti` 落在函数尾、I/O 地址全部落在 0x7000 段且与手册寄存器一一对应。

### 3.1 编码结构（16 位定长）

| 位域 | 含义 |
|---|---|
| `[15:12]` | 操作码：0 add / 1 adc / 2 sub / 3 sbc / 4 cmp / 6 neg / 8 xor / 9 load / A or / B and / C test / D store / E、F 专用组 |
| `[11:9]` | 目标寄存器 A（0=sp,1=r1,2=r2,3=r3,4=r4,5=bp,6=sr,7=pc） |
| `[8:6]` | 寻址模式：0 `[bp+imm6]`、1 立即数、2 pop/push、3 间接、4 寄存器/立即数16/直接地址/移位、5 lsl/lsr、6 rol/ror、7 短直接地址 |
| `[5:3]` | 子字段（间接寻址方式 / 移位方式 / 寄存器选择） |
| `[2:0]` | 源寄存器 B |

特殊约定：`[11:9]==7` 且 `[8:6]<2` 时是**单字条件/无条件相对跳转**，`[15:12]` 直接是条件码（`jb/jae/jge/jl/jne/je/jpl/jmi/jbe/ja/jle/jg/jvc/jvs/jmp`），`[8:6]` 选择前向/后向，`[5:0]` 是位移。

**写 PC 的 ALU 指令即跳转**（手册也注明 Rd=PC 时周期变长、标志位不变）。本固件中编译器用它实现长跳转：`9F0F xxxx` = `pc = xxxx`（双字，双字指令）；`0xF040 xxxx` = `call xxxx`。

## 4. 启动流程（复位 → 主循环）

### 4.1 复位入口 `0xCB9F`

```
CB9F: sp = 0x07FF           ; 建立栈指针（RAM 顶）
CBA1: r1 = 0x824B           ; 指向 C 运行时"初始化数据拷贝表"
CBA3: r2 = [r1++]           ; 记录条数
CBA4: jmp 0xCBB6
CBA5: push r2, r2 to [sp]   ; 每条记录：
CBA6: r3 = [r1++]           ;   目标地址
CBA7: r4 = [r1++]           ;   段选择（<<10 → SR 的 DS 字段）
CBA8: r4 = r4 lsl 4
CBA9: r4 = r4 lsl 4
CBAA: r4 = r4 lsl 2
CBAB: sr = r4
CBAC: r4 = [r1++]           ;   源地址
CBAD: bp = [r1++]           ;   长度
CBAF: r2 = ds:[r4++]        ;   逐字搬运（带段前缀）
CBB0: [r3++] = r2
CBB1: bp -= 0x01
CBB2: cmp bp, 0x00
CBB3: jg 0xCBAF
CBB4: pop r2, r2 from [sp]
CBB5: r2 -= 0x01
CBB6: cmp r2, 0x00
CBB7: jg 0xCBA5
CBB8: call 0x8205           ; ★ 进入常规启动
CBBA: jmp 0xCBBA            ; 死循环兜底
```

拷贝表在 `0x824B`，本映像里 9 个字全为 0，即**没有需要初始化的数据段**（编译器把变量放在被启动代码清零的区里）。

### 4.2 常规启动 `0x8205`

| 地址 | 代码 | 说明 |
|---|---|---|
| 8205-8206 | `fiq off` / `irq off` | 关中断 |
| 8207-820D | `r1=0; r2=0; r3=0x07FF; [r2++]=r1; cmp; jne` | **清零 RAM 0x0000-0x07FF** |
| 820E-8212 | `bp=0x55F0; bp-=1; jne` | 上电延时（等待电源/时钟稳定） |
| 8213 | `sp = 0x07FF` | 再设栈 |
| 8215-8216 | `r1=1; [0x7012]=r1` | 清看门狗 P_Watchdog_Clear |
| 8218 | `call 0xCB2B` | I/O 端口初始化（见下） |
| 821A | `call 0x823A` | 等待外部/从设备就绪（见下） |
| 821C-8230 | 循环 `call 0xCDC4`、比较 `0x0FCC/0x0ABB/0xFABB`、`call 0xCDB3`/`0xCFC8` | 与对端握手/上报状态码 |
| 8232-8239 | `[0x7012]=1; call 0xCE0D; call 0xC5E5; jmp 0x8232` | **主循环**：喂狗 → 命令分派 → 状态机 |

`0xCB2B` = I/O 初始化：写 `P_IOA_DIR/P_IOA_ATTRIB/P_IOA_DATA`(0x7000-0x7003)、`P_IOB_DIR/P_IOB_ATTRIB`(0x7007/0x7008)，并组装 A/B 口方向与属性常数（0x4400/0xFF7B、0x4480/0xFFFB、0x4404/0xFF7F、0x8000…）。

`0x823A` = 握手/等待例程：循环 `call 0xCDB3`（从环形缓冲取一个字节）直到等于 `0x0ABB`，然后 `call 0xCFC8` 上报 `0xFABB`。`0xCFC8` 是把字按高低半字节经 UART 输出的调试/协议输出例程（→ `0xCFBF` → `0xCFD3`，后者轮询 `P_UART_COMMAND2`(0x7022) 并写 `P_UART_DATA`(0x7023)）。

## 5. 中断系统

### 5.1 向量表（`0xFC00`，11 项）

```
FC00: C889   FC01: C742   FC02: CB9F   FC03..FC09: C895 ×7   FC0A: C889
```

与手册 11 个向量（`_BREAK / _FIQ / _RESET / _IRQ0.._IRQ7`）逐项对应，语义完全讲得通：

| 项 | 值 | 处理程序 |
|---|---|---|
| `_RESET` | `CB9F` | 复位入口（4.1 节）✓ |
| `_FIQ` | `C742` | 音频 FIQ：ADC 采样 → DAC2 输出（5.2 节）✓ |
| `_IRQ7` (UART) | `C889` | UART 收中断（5.3 节）✓ |
| `_IRQ0.._IRQ6` | `C895` | 统一"清全部中断标志后返回"的默认处理程序 ✓ |
| `_BREAK` | `C889` | 与 UART 处理程序同址（软件断点/调试入口复用） |

### 5.2 音频 FIQ `0xC742`

```
C742: push r1, bp to [sp]
C743: r1 = [0x0000]        ; 软件标志/状态字
C745: test r1, 0x0800
C747: je 0xC74A
C748: pc = 0xC7D8          ; 另一条分支（旁路处理）
C74A: test r1, 0x1000
C74C: jne 0xC753
C74D: r1 = 0x2000
C74F: [0x7011] = r1        ; P_INT_CLEAR（非本中断源，清标志）
C751: pop r1, bp from [sp]
C752: reti
C753: bp = [0x076E]
C755: [0x7016] = bp        ; P_DAC2 ← 输出样本
C757: bp = [0x076F]        ; 相位/拍号
C759: r4 = bp + 1
C75B: r4 &= 0x03
C75C: [0x076F] = r4        ; 4 相位循环
C75E: bp = bp lsl 4        ; 每相位 16 字
C75F: bp = bp + 0xC70A     ; 系数表基址（数据区）
C761: bp = bp - [0x0785]   ; 减去采样环形缓冲索引
C763: r2 = 0x0765          ; 32 点采样缓冲
C765: MR = [r2]*[bp], ss, 8   ; MULS 8 位乘法
C766: r3 = [0x0001]        ; 软件状态/系数
C768: MR = r3*r4, us
C769.. 限幅判断（0x0FFC / 0xF000）→ 输出回 DAC
```

另一条采样中断（同属 FIQ 组，`0xC7E3` 起）负责采集：

```
C7EB: r4 = [0x7014]        ; P_ADC
C7ED: r4 = r4 ^ 0x8000     ; 无符号 → 有符号（DAC/ADC 中点 0x8000）
C7EF: [bp] = r4            ; 存入 0x0765 起 32 字环形缓冲
C7E9: [0x0785] = r4        ; 缓冲写指针（&0x1F）
```

即：**ADC 采样中断 + 相位查表乘法中断**构成音频输出链路，系数表在数据区 `0xC70A` 附近（每相位 16 字，共 4 相位），用 `MULS ... ss, 8` 做 8 位乘法，符合 SPCE061A 语音/音乐应用的典型做法。

### 5.3 UART 中断 `0xC889`

```
C889: push r1, bp to [sp]
C88A: r2 = [0x7022]        ; P_UART_COMMAND2
C88C: test r2, 0x0080      ; RxRDY?
C88E: je 0xC893
C88F: r1 = [0x7023]        ; P_UART_DATA
C891: call 0xCC23          ; 收字节处理（入环形缓冲 0x075B-0x0764）
C893: pop r1, bp from [sp]
C894: reti
```

### 5.4 默认中断处理 `0xC895`

```
C895: jmp 0xC896 / 0xC896: jmp 0xC897   ; 2 条"跳转到下一条"＝延时/占位
C897: r1 = 0xFFFF
C899: [0x7011] = r1                      ; 清全部中断标志
C89B: reti
```

### 5.5 中断使能/屏蔽

- `P_INT_CTRL(0x7010)` 写 6 处：`0xC8A9`（写 0x2000，使能 FIQ 组）、其余在初始化/状态切换中。
- `P_INT_CLEAR(0x7011)` 14 处、`P_Watchdog_Clear(0x7012)` 17 处（覆盖所有长循环）。
- `irq on` 2 处（`0xCB0D`、`0xCF01`）、`irq off` 3 处、`fiq on/off` 33 处——多处成对出现，构成临界区（例如 `0xAC42`：`fiq off` → 读改写 `[0x0000]` 标志字 → `fiq on`）。

## 6. 主循环与命令分派

**主循环 `0x8232`**：

```
8232: r1 = 0x01
8233: [0x7012] = r1     ; 喂狗
8235: call 0xCE0D       ; 命令/事件分派
8237: call 0xC5E5       ; 状态机（含 DAC/PWM/ADC 相关处理）
8239: jmp 0x8232
```

**分派 `0xCE0D`**：读软件标志字 `[0x0000]` → 取环形缓冲字节（`0xCDB3`）→ 按**低半字节查表跳转**：

```
CE17: call 0xCDB3          ; 取一个字节
CE19: cmp r1, 0x00 / je ...
CE1B: r2 = r1 lsr 4 ...    ; 高半字节 → 参数
CE1D: r3 = r1 & 0x000F     ; 低半字节 → 索引
CE1F: r3 = r3 + 0xCB72     ; 分派表
CE21: r3 = [r3]
CE22: pc = r3              ; 间接跳转
```

分派表 `0xCB72`（16 项）指向 16 个处理分支：`CE24 CE24 CE24 CE24 CE26 CE2B CE30 CE35 CE3A CE3F CE7B CF5A CF89 CE80 CEB6 CF2A`。各分支再执行具体命令（读 ID 记录并上报、设置参数、控制音频、UART 应答等）。

另外发现 **10 张指向代码的指针表**（清单见附表），例如：

| 表地址 | 项数 | 用途 |
|---|---|---|
| `0xCB72` | 16 | 主命令分派 |
| `0xCB7F/0xCB89/0xCB8F` | 各 8-16 | 子命令/参数分派 |
| `0xCAE3` | 多 | 事件分派 |
| `0x994D`、`0x9E98`、`0xACD3`、`0xAD48`、`0xB166` | 8-13 | 功能分派 |
| `0xB4D6` | 8+ | 处理程序表（`82C8 831E 8378 83D7 843C 84A4 8512 8584`，等间距代码块） |
| `0xFC00` | 11 | 中断/复位向量表 |

## 7. RAM 使用（0x0000-0x07FF）

启动时全清零，之后固件主要使用以下几个区域（完整表见附表）：

| 地址 | 访问量(写/读) | 推断用途 |
|---|---|---|
| `0x0000` | 28 / 36 | **软件标志/状态字**：`0x0400`、`0x0800`、`0x1000`、`0x4000`、`0x8000` 等位；多处 `fiq off/on` 保护读改写 |
| `0x0001` | 2 / 1 | 音频相关参数（`0xC428`、`0xC565` 写，`0xC766` 在 FIQ 中读） |
| `0x0002-0x0005` | - | 初始化参数块（`0xC42A` 起写入 0x0C、0x02、0x02、0x02） |
| `0x037D-0x037E` | 9 / 26 | 计数器/状态 |
| `0x043A-0x043B` | - | 指针/索引（`0xB4xx` 排序例程用） |
| `0x04A2-0x04D5` | 多 | 主状态区（`0x04CF/0x04D0` 缓冲写指针、`0x04D4/0x04D5` 长度/索引） |
| `0x0504-0x0548` | 多 | 参数/中间结果（`0x0545`、`0x0548` 读写频繁） |
| `0x06D1-0x06EB` | 多 | 计数/统计（`0x06D7-0x06DC`、`0x06EA/0x06EB`） |
| `0x0763-0x0764` | - | **UART 收环形缓冲的读写指针**（缓冲 `0x075B-0x0762`，9 字节，`0xCDB3`取/`0xCDC4`查） |
| `0x0765-0x0784` | - | **32 字音频采样环形缓冲**（FIQ 写，处理程序读） |
| `0x076E-0x076F` | - | DAC 输出值 / 相位计数 |
| `0x0785` | - | 环形缓冲写指针（`&0x1F`） |
| `0x0794-0x0796` | - | 调试/上报暂存（`0xCFC8` 拆半字节后送 UART；`0x0796` 为运行标志） |

## 10. 遗留问题与建议

1. **向量区落位需要核对**：本映像里 CPU 层面的向量区 `0xFFF5-0xFFFF` 是擦除态，而 11 项向量值出现在 `0xFC00`。手册明确 `0xFC00~0xFFFF` 为系统保留区、`0xFFF5~0xFFFF` 为向量区，因此最合理的解释是：**下载工具/ICE 在烧写时把 `0xFC00` 起的 11 个字装到真正的向量区**（或 0x8000-0x81FF 的系统监视程序负责安装）。建议用编程器读一次芯片的 `0xFFF5-0xFFFF` 与 `0x8000-0x81FF`（这两个区域都不在本 `.dat` 里）来确认。
2. **0x8000-0x81FF 不在映像中**：程序区从 0x8200 开始，前 512 字（IDE/ICE 监视程序区）没有在 dump 里；如果你能补上这段，可以进一步确认复位向量的安装过程。
3. **功能语义命名**：表格化的子程序名目前是 `sub_xxxx`。若你能提供 IDE 源工程（`.spj`/`.asm`）或符号表，我可以把 165 个子程序与真实函数名、变量名一一对应，反汇编会立刻可读得多。
4. **音频数据可继续解码**：高熵区（`0xD2E3-0xFBFF`、`0x8800-0x9E00`）很可能是 SPCE061A 常见的音频压缩格式（SACM-A2000/ADPCM 等）。若要还原语音内容，需要先确认压缩算法（第 7 章《凌阳音频压缩算法》PDF 已在你给的资料包里），我可以据此写解码脚本并试听。
5. **未解引用代码**：约 15% 的代码字仅能通过"计算跳转 + 内联代码片段表"到达（如 `0xB7xx` 区的 `pc += r3` 分派、`0x881F` 等块）。清单里这些块已按指令正确反汇编，但调用关系未连边，可作为下一步细化方向。
