## 1. 快速上手

### 1.1 编译

```powershell
cd src_nc3000
.\build.ps1               # -> nc3000.exe（GUI，64 位）
.\build.ps1 -Headless     # -> nc3000_headless.exe（无窗口调试台，64 位）
.\build.ps1 -XP           # -> nc3000_xp.exe（32 位，能在 32 位 WinXP 上跑）
.\build.ps1 -XP -Headless # -> nc3000_xp_headless.exe
```

工具链在 `../toolchain`（mingw-w64 GCC + SDL2），**不需要装任何东西**。
GUI 版是 `-mwindows` + **静态链接**（连 SDL2 都静态链进去了），所以 exe 单文件就能跑，
不依赖 `libwinpthread-1.dll` / `libstdc++-6.dll` / `SDL2.dll` 之类。

#### 32 位 / WinXP 版（`-XP`）

默认的 exe 是 **x86-64 + UCRT**，导入 `api-ms-win-crt-*`——**32 位 XP 一定跑不了**，
这不是加个参数能解决的，得换一整套工具链。三根硬门槛：

1. **必须 32 位**（i686）；
2. **必须链 `msvcrt.dll`**，不能链 UCRT；
3. **SDL2 只能用 2.0.22 或更早**（2.24 起官方放弃 XP）。

所以 `-XP` 走的是另一套目录：

| 用途 | x64（默认） | 32 位 XP（`-XP`） |
|---|---|---|
| 编译器 | `toolchain/mingw64/mingw64`（UCRT）| `toolchain/mingw32`（**i686 + msvcrt**，GCC 16.2.0）|
| SDL2 | `toolchain/sdl2/SDL2-2.32.10` | `toolchain/sdl2_xp/i686-w64-mingw32`（**2.0.22**）|
| 宏 | — | `-D_WIN32_WINNT=0x0501 -DWINVER=0x0501` |
| 中间产物 | `obj/` | `obj_xp32/`（两套架构不能混用）|
| 输出 | `nc3000.exe` / `nc3000_headless.exe` | `nc3000_xp.exe` / `nc3000_xp_headless.exe` |

运行方式和 x64 版一样（也要先切到 `src_nc3000`，见 1.2 的说明）：

```powershell
.\run_nc3000_xp.cmd                  # 双击也行
src_nc3000\nc3000_xp.exe --console   # 想同时看 printf 日志时加这个
```

**自检**（换过工具链/SDL2 之后建议跑一遍）：

```powershell
& toolchain\mingw32\bin\objdump.exe -f src_nc3000\nc3000_xp.exe    # 要 pei-i386
& toolchain\mingw32\bin\objdump.exe -p src_nc3000\nc3000_xp.exe |
    Select-String "DLL Name"
```

期望的导入表只有 XP 那几支：`KERNEL32 / USER32 / GDI32 / WINMM / IMM32 / ADVAPI32 /
SHELL32 / ole32 / OLEAUT32 / VERSION / SETUPAPI / msvcrt`；
**出现任何 `api-ms-win-crt-*` 就是链错了 runtime**。

**等价性验证**：32 位无头版和 64 位无头版跑同一串按键，输出的每一帧液晶都是
**逐字节相同**（word size 变化不影响模拟结果）。

### 1.2 运行

```powershell
.\run_nc3000.cmd                 # 双击也行：自动找 ROM，切到 src_nc3000 再启动
src_nc3000\nc3000.exe            # 直接双击 exe 也可以（ROM 会自动探测）
src_nc3000\nc3000.exe --console  # 想同时看 printf 日志时加这个
src_nc3000\nc3000.exe --rom roms\nc3000_dl\nc3000     # 指定 ROM
```

#### 独立绿色包（可以整个文件夹搬到任何地方）

把 exe + ROM 单独拷出来也能跑，推荐这样摆（`C:\Users\YYGSM\Documents\work\nc3k_emu` 就是这么放的）：

```
nc3k_emu\
  run_nc3000.cmd         ← 双击即用（64 位版）
  run_nc3000_xp.cmd      ← 双击即用（32 位 / XP 版）
  bin\nc3000.exe         （+ nc3000_xp.exe）
  bin\resource\...       ← 液晶皮肤(2 个 bmp + 2 个 json)，**必须跟着 exe**
  bin\wqxhex.bin         ← 可选，只有内置 wqxhex 调试命令会用到
  roms\nc3000.nor / .nand / .nand0
```

两个 cmd **完全按 `%~dp0` 定位**，跟当前工作目录无关，所以整个文件夹可以随便搬
（换盘符、带空格的中文路径都行）。它们还会：

* 找不到 exe / ROM 时给明确提示并 `pause`（不会一闪而过）；
* 把**拖进来的 `.nor`** 当成 ROM（后面跟着的其它参数照常透传给模拟器）；
* 额外参数原样透传，例如 `run_nc3000.cmd --console`。

> 皮肤的查找顺序（`main.cpp` 的 `resolve_resource_path`）：先当前目录的 `resource\`，
> 再 **exe 同目录的 `resource\`** —— 所以脚本把工作目录切到 `bin\`，皮肤放在 `bin\resource\` 就一定找得到。
> 反过来，如果搬 exe 时**忘了带 `resource\`**，窗口会开但液晶区是空的/花屏。

开机流程（**必须认识这几步**）：

```
系统空间整理中…  →  闪存中有数据 清除吗？Y清除，N保留   ← 按 N
   →  名片数据正在整理中…  →  授权画面 ⇄ NC3000 LOGO（每秒翻一次）
   →  按【输入】进 2×6 系统菜单；按顶排热键则直接进对应功能
```

### 1.3 ROM 从哪来、怎么装（★ 最容易搞错的地方）

```powershell
powershell -File tools\nc3000_rom_prep.ps1     # info/*.nor + *.nand -> roms/nc3000.*
```

> 脚本会**自动补齐 dump 里缺的两块**（都会打印提示）：
> ① `.nand` 的页对齐（见下表）；② NOR `0xED000` 的**产品信息**——
> 老 dump 只导出了 17 个 bank，缺这块的话固件会在进主菜单前弹
> "产品信息有误 请接洽代理商"（机型字段按 NC3000 合成；真机序列号需要完整 dump）。

| 文件 | 内容 |
|---|---|
| `<rom>.nor` | **1 MB**，32 个 bank × 32 KB，**芯片线性顺序**（dump 是 CPU 窗口顺序，bank≥1 的上下 16 KB 要对调）|
| `<rom>.nand0` | 设备 NAND 的**第 0~63 页**（64 × 528 = 33,792 B）。可以全 `FF`——模拟器会自己写 `"ggv nc3000"` 签名 |
| `<rom>.nand` | 设备 NAND 的**第 64 页到末尾**（**不是**"整个 NAND"！）|

> ⚠️ 两个坑都踩过：
> 1. `.nand` 装错（把"整个 NAND"塞进去）会**整体偏移 64 页**，固件跑飞；
> 2. 反过来，**从设备第 64 页开始 dump 的镜像**如果又被切掉 64 页，同样错位——
>    固件在"闪存中有数据 清除吗"选 N 之后会因为挂不上文件系统而**掉进它自己的调试监视器
>    （屏幕只剩一个 `>`）**。`tools/nc3000_rom_prep.ps1` 现在会自动判断（看第 0 字节是不是 inode 1）。

三套现成 ROM（启动时自动探测，优先第一套，日志会打印 `rom auto-detected: …`）：

| 路径 | 是什么 |
|---|---|
| `roms/nc3000.*` | **用户自己那台机器**的 dump（`info/NC3KSYSNOR.nor` + `NC3KSYSNAND.nand`），带用户机上的数据 |
| `roms/nc3000_dl/` | 本仓库一路验证用的参照 ROM（Lee 的 3.4 集），里面还装了 `音乐1.mid`/`音乐2.mid` |
| `roms/lee2/` | Lee 发行包原样（未改动） |

### 1.4 往虚拟盘里加文件

```powershell
powershell -NoProfile -File tools\nc3k_put.ps1 -Rom roms\nc3000_dl `
    -File "info\NC3000原机的midi\音乐1.mid" -Name "/midi/音乐1.mid"
```

原理（**关键**）：用固件自己的 FS API `open($088d)` → `write` → `close`，
**最后必须再调 `INT $051C`(InodeReclaimAll)**，inode 日志才会被整理生效。
少了这一步，open/write/close 全返回成功、NAND 字节也都写对了，但开机后目录仍然是空的。
细节见 `NC3000_NAND_文件系统分析.md` §8。

### 1.5 常用调试开关（都在无头版上）

| 开关 | 用途 |
|---|---|
| `--ms N` | 跑 N 个模拟毫秒（1 ms = 14745 周期 ≈ 14.7456 MHz）|
| `--press <ms> <y> <x>` / `--hold N` | 到点按矩阵 (y,x)，按住 N 毫秒 |
| `--dump-lcd f.bmp` / `--lcd-seq <ms> <前缀>` | dump 液晶画面（单帧 / 每 N ms 一帧）|
| `--watch-write <addr>` | **谁**写了这个内存地址（带 PC/寄存器）——最好用的一招 |
| `--watch <pc>` / `--ring <pc>` | 断点 / 命中时 dump 最近 N 条指令 |
| `--io-watch <port>` / `--io-rwatch <port>` | 记录某 IO 口的写 / 读 |
| `--nand-after <ms>` / `--nand-watch-sector <S>` | 从某时刻起记录 NAND 读、盯某个扇区 |
| `--dump-061 <f.wav>` / `--uart-log N` | 抓 061 的原始 DAC 流 / 打印链路包 |
| `--cmd-at <ms> "<命令>"`、`--cmd-file <ms> <文件>` | 定时执行模拟器内置命令（`put`/`call`/`save_flash`…；`cmd-file` 走原始字节，能传 GBK 文件名）|
| `call1 <idx> <bank>` | 和 `call` 一样发 INT，但**只发一次**并把返回进位记到 `$03F0`（1=成功）。查"系统自测某项到底过没过"用这个——`call` 那个桩会不停重发，最终结果只闪现几毫秒 |
| `--save-flash <前缀>` | 跑完把 nor/nand 落盘 |
| 环境变量 `NC3_NO_BEEPER=1` / `NC3_SND_DEBUG=1` | 关蜂鸣器 / 打印重采样状态 |
| 环境变量 `NC3_DSP_NAND=1` | 061 固件换成 NAND 里的 `升级061.bin`(284F)。**默认是 `061.dat`(283D)** —— 真机的 DSP 就是这版（自测读数 `f7 10 3b 30` / `3d 28` 对得上）|
| 环境变量 `NC3_DSP_FIX_HEADER=1` | 允许在**内存副本**里按固件算法补写 061 映像的校验和标头（只对两对标头不一致的映像生效，也就是 NAND 那份 284F）。**默认关闭 ⇒ 061 映像一个字节都不改**；开了自检才可能过（见改造计划 §22.9）|

辅助脚本：`tools/sweep_keys.ps1`（穷举 128 个键位看固件解出什么键值）、
`tools/nc3kfs.py`（NAND/NOR 的 FS 解析）、`tools/bindiff.py`（二进制对拍）、
`tools/lee_win.ps1` + `tools/screengrab.ps1`（操作/截图 Lee 版模拟器窗口）、

## 3. 结论速查（不用翻日志）

### 3.1 硬件与地址空间

* 主控 SPDC1064：6502 兼容核，**14.7456 MHz**（手册 PLL 正常运行模式；1 ms = 14745.6 周期，
  `CYCLES_MS = 14745`），
  NOR 1 MB（32 × 32 KB bank）+ NAND 64 MB（528 B/页）+ SPCE061A 语音 DSP。
* CPU 窗口：`4000-BFFF` 是 4×8KB 主窗口（`io_bank_switch` 选 bank）、
  `C000-DFFF` 是 8KB 映像窗（BBS）、`E000-FFFF` 是固定 BIOS；
  bank 0 在 `8000-FFFF`，其余 bank 在 `4000-BFFF`。
* `INT`（BRK）三字节：`00 <idx> <bank>`；表项在 `基址 + 2*idx`。
  详见 `NC3KSYSNOR_结构分析.md`。
* 主控 ↔ 061 走 **UART `0x3A-0x3D`**（不是 NC2000 那组并行口），握手线 `IO 0x0E` bit4
  （ready，输入）；**同一个口的 bit3 是 061 的 `/RESET`（输出，低有效）** —— BIOS 每次要跟
  061 说话前都会脉冲一次，复位后 `CC 0F` 才回 `CC FF`（自测第 9 项就靠这个，详见
  `NC3000_DSP检测与升级.md` §7）。

### 3.2 键盘

一句话：**16 列 × 8 行**，列 = 主键盘的"排"，行 = 每排第几个。
顶排 8 个热键在**列 0**，字母区在**列 4~7**，`输入/⇟/→/O/L/↑/↓/P` 和 `插入~修改` 在
**列 1/2**（走 port6），侧面两个键走**列计数器的槽位 8/9**。
完整表格与 PC 键位见 `NC3000_键盘.md`。

### 3.3 启动与菜单

* 冷启动会问"闪存中有数据 清除吗"，**按 N 保留**；之后是"名片数据整理"→ 授权⇄LOGO。
* LOGO 画面上：按**输入**进 2×6 主菜单；按**热键**直接进对应功能；再按同一热键切副功能
  （12 个标签 = 6 个键 ×2 档）；按 ON/OFF 关机。
* 主菜单 12 项：第一行 英汉/AHD/剑桥/PDA/计算/时间，第二行 汉英/词库/学习/游戏/换算/系统。
* 进了功能之后**不能按跳出回主菜单**（真机也这样），要休眠再唤醒。

### 3.4 声音

* 061 的**默认固件是外挂的 `spce061a/rom/061.dat`（283D，真机出厂同款）** ——
  真机自测读数 `Check_Sum: f7 10 3b 30` / `Version: 3d 28` 与它一字不差。
  NAND 里的 `sysdir/升级061.bin`（284F）是**随机器带的升级包**（而且是"待烧写映像"，
  校验区前一对是全 `0000`）：只有 `NC3_DSP_NAND=1` 才切过去，想让它自检通过还得再加
  `NC3_DSP_FIX_HEADER=1`（两个开关默认都关，**默认一个字节都不改**，见改造计划 §22.9）。
  （早期阶段默认加载的确实是 NAND 那份，日志打 `[061] NAND 升级061.bin(284F) firmware, reset entry $xxxx`；
  2026-09-27 拿到真机读数后改成默认 `061.dat`，见改造计划 §22.7。）
* 主控 → 061：`0xBB` 握手 → `0x99 0x21` 选解码器 → `0x33`+15 字节块 / MS01 音乐命令。
* 061 的指令预算 = 主控周期 × **10/3**（061 晶振 49.152 MHz ÷ 主控 14.7456 MHz 的精确比值）；
  061 的指令率 = **49.152 M/s**（`N3_INSN_PER_SEC`），DAC 采样数按它折算。
* 主机侧音频队列有**背压**（目标 ≈3000 样本 ≈ 47 ms），真机 DAC FIFO 很小，解码器不会跑到 DAC 前面。
* 曾经导致噪音的 bug（包型、DAC 时基、指令预算、ready 线、以及第 18 节的速率/背压/`0x0000`）
  都已修，见改造计划第 10、18 节。

### 3.5 文件系统

```
FS 扇区 N  ↔  NAND 设备页 32*N                （恒等，没有坏块重映射）
.nand 文件偏移 = (设备页 - 64) * 528
一个扇区 = 32 × 528 = 16,896 字节
目录块 = 16 字节条目 [2B inode][14B GBK 名]，写在 blk[0] 扇区的页 0（条目从 +0x10 开始）
inode 表 = 32 字节/条、槽位 (id-1)*0x20、以 A8 A8 结尾；NOR 里有两份世代（0xFC000 / 0xFD000），
           更新走"日志 + INT $051C 整理"
```

### 3.6 时基

GUI 是"1 个真实毫秒跑一片 `RunTimeSlice(1)`"，而 `RunTimeSlice` 以前会多跑约 25 周期
（10265/ms，快 0.24%）。现在有跨片补偿，长期速率精确等于 `CYCLES_MS`（**14745 周期/毫秒**），
且 061 的音频流与改动前**逐样本一致**。

> 📌 **主频是 14.7456 MHz，不是 10.24 MHz**：上游 NC2000 模拟器的 nc3000 分支按 10.24 MHz 算
> （≈ NC2000 的 5.12 MHz × 2），导致所有"由 CPU 指令时间决定"的东西慢了 1.44 倍——
> 最明显的就是**蜂鸣器音调偏低**（6.9 kHz vs 真机 ~9.9 kHz）。2026-09-27 按 SPDC1064 手册
> （正常运行模式 PLL = 14.7456 MHz，且固件开机就把 CKS 设成 OSC）改掉，见改造计划第 19 节。

### 3.7 两套 ROM 的差异（真机 dump vs Lee 的参照集）

* 两套都是 3.4，但**不是同一份 dump**：NAND 容量不同（用户机 53.7 MB 数据区 vs Lee 64 MB），
  内容也不同——用户机 网络 菜单是 `托福试题/有声读物/旅游全球话`，Lee 集是
  `应用程序/文书浏览/有声学习/和弦音乐/歌曲音乐`。
* 之前"apple 发音对不上"的结论是拿真机录音对比 **Lee 的 ROM** 得出的；
  现在用户自己的 dump 已经能跑，**可以再复核一次**（把 `roms/nc3000` 当 ROM 起，
  查 apple 按发音键，再和 `out/nc3000/真人录音/apple_real.wav` 比）。
